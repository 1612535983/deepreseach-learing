# 证据化报告写作

适用于研究已经接近完成，需要把计划、证据和限制整理成最终 Markdown 报告的阶段。

## 报告结构

1. 开头直接给出结论摘要，回答用户真正关心的问题。
2. 正文按研究子问题组织，而不是按 Tool 调用时间线罗列。
3. 每个关键事实就近附上实际读取过的来源链接。
4. 单独说明证据不足、来源冲突、时效边界和必要推断。
5. 结尾给出简短结论或可执行建议，避免重复整篇正文。

## 提交前检查

- 计划步骤已经完成或明确标记失败；
- 报告中的 URL 来自本轮已收集来源，并且确实出现在正文中；
- 没有把搜索摘要、模型常识或推测伪装成已验证事实；
- 在 P5 收尾阶段只整理现有证据，不再扩张研究范围。
